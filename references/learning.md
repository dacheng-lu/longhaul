# SECI-inspired learning and optional rune diagnostics

Separate recovery state from reusable knowledge. Use SECI as an analogy, not evidence of human-like tacit learning or weight updates.

| Mode | Task behavior | Evidence |
|---|---|---|
| S: shared practice | Observe demonstrations, corrections or a worked case | Concrete observations in context; text exchange is not necessarily tacit-to-tacit transfer |
| E: articulation | Express a candidate rule | Rule, rationale, scope and uncertainty |
| C: combination | Compare with existing rules and primary sources | Resolved or marked conflicts and integrated procedure |
| I: practice | Apply to a materially different case | Observed results and limitations; saving a rule is not learning |

Store lessons with context, observed result, candidate rule, evidence, counterexamples, status (candidate/tested/rejected), and next test. Do not universalize one example. Change permanent skills only when requested or explicitly authorized, using skill management.

Use these labels only when helpful. They are operational interpretations of the user's cards, not historical or predictive claims.

| Labels | Diagnostic |
|---|---|
| Sowilo | Is the target and success evidence explicit? |
| Berkana / Uruz | Is there a feasible next action and room for incremental improvement? |
| Othala / Teiwaz | Which inherited assumption needs examination? What supports it? |
| Wyrd / Mannaz | How do prior work, context, people and dependencies affect the next step? |
| Laguz / Perthro | What is unknown? Which small experiment separates explanations? |
| Dagaz | Does evidence require a changed model or method? |
| Thurisaz / Ansuz | What does resistance reveal? Can the failure be described precisely? |
| Jera / Kenaz | What useful result accumulated? Does the method transfer? |

Evaluate against a simpler baseline: recovery accuracy, duplicated effort, unsupported completion claims, quality, user questions and total effort. Remove ceremony with no benefit.

SECI source: Nonaka, Toyama and Konno (2000), https://doi.org/10.1016/S0024-6301(99)00115-6 . The AI operationalization is a proposal, not a finding of that paper.
